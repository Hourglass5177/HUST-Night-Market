# 随机系统策划案 — HUST Night-Market

## 一、概述

随机系统包含三大子系统：**随机事件(EventManager)**、**天气系统(WeatherManager)** 和 **卫生审查(InspectionManager)**。它们共同为游戏引入不确定性，增加复玩性和策略深度。

---

## 二、随机事件系统（EventManager）

### 2.1 设计目的

玩家在校园地图上移动和经营夜市时会遇到各种随机事件，这些事件可能带来收益或风险，需要玩家做出选择或承担后果。

### 2.2 事件触发时机

| 触发时机 | 枚举值 | 说明 |
|---------|--------|------|
| 到达地块 | `OnArriveTile` | 玩家棋子到达某个地块时，从该地块的 eventPoolId 对应的事件池中抽取事件 |
| 每天开始 | `OnDayStart` | 每天 DayStart 阶段，全局概率触发 |
| 夜晚开始 | `OnNightStart` | 进入 NightSettlement 前触发 |
| 结算过程中 | `OnSettlement` | 夜晚收入计算过程中触发 |
| 卫生检查 | `OnInspection` | 卫生检查时触发，可能影响检查结果 |
| 手动触发 | `Manual` | 测试或特殊地块专用 |

### 2.3 事件效果类型

| 效果类型 | 枚举值 | 效果说明 | 数值范围参考 |
|---------|--------|---------|:-----------:|
| 无效果 | `None` | 纯文本事件，无数值变化 | — |
| 增减资金 | `AddMoney` | 直接修改玩家现金 | ±200 ~ ±5000 |
| 增减低端食材 | `AddLowFood` | 修改低端食材数量 | ±5 ~ ±30 |
| 增减高端食材 | `AddHighFood` | 修改高端食材数量 | ±2 ~ ±15 |
| 增减口碑 | `AddReputation` | 修改夜市口碑值 | ±5 ~ ±50 |
| 增减体力 | `AddEnergy` | 修改玩家体力 | ±5 ~ ±20 |
| 修改客流 | `ModifyTraffic` | 按百分比影响当晚客流 | ±10% ~ ±30% |
| 修改竞争 | `ModifyCompetition` | 修改地块竞争强度 | ±5 ~ ±20 |
| 修改卫生 | `ModifyHygiene` | 修改夜市总卫生值 | ±5 ~ ±15 |
| 强制检查 | `TriggerInspection` | 立即触发一次卫生检查 | — |
| 夜市停业 | `CloseMarket` | 夜市停业 N 天 | 1 ~ 3 天 |

### 2.4 GameEvent 数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `eventId` | string | 事件唯一ID，如 EVT_MONEY_WIND |
| `eventName` | string | 事件显示名称 |
| `eventDescription` | string | 事件描述文本（可显示在 UI 上） |
| `triggerType` | EventTriggerType | 触发时机 |
| `effectType` | EventEffectType | 效果类型 |
| `effectValue` | int | 效果数值（正=增益，负=减益） |
| `probability` | float | 触发概率（0.0~1.0），默认 0.1 |
| `eventPoolId` | string | 所属事件池ID，如 EVENT_POOL_ARRIVE |
| `requireChoice` | bool | 是否需要玩家二选一 |
| `choiceAText` | string | 选项A的文本 |
| `choiceAValue` | int | 选项A的效果值 |
| `choiceBText` | string | 选项B的文本 |
| `choiceBValue` | int | 选项B的效果值 |

### 2.5 事件池设计

事件池按用途分组：

| 事件池ID | 用途 | 事件示例 |
|---------|------|---------|
| EVENT_POOL_ARRIVE | 到达地块触发 | "发现钱包"→+200元 / "小贩推销"→-300元 |
| EVENT_POOL_DAY_START | 每天开始触发 | "社团活动"→+口碑 / "食材促销"→+低端食材 |
| EVENT_POOL_NIGHT | 夜晚开始触发 | "突然下雨"→客流-20% / "节日加成"→收入+30% |
| EVENT_POOL_INSPECTION | 卫生检查时触发 | "熟人检查"→跳过检查 / "举报"→检查概率+50% |

### 2.6 事件触发流程

```
触发事件(TriggerType)
  │
  ├─ 过滤事件池中所有符合 triggerType 的候选事件
  │
  ├─ 对每个候选事件：
  │    ├─ Random.value < probability? → 触发
  │    │    ├─ requireChoice? → 记住事件，等待 UI 回调 MakeEventChoice()
  │    │    └─ !requireChoice? → 直接执行 ExecuteEventEffect()
  │    └─ 否则 → 跳过
  │
  └─ 返回所有被触发的事件列表（含 EventRuntimeData）
```

### 2.7 二选一事件示例

```
事件：发现一批廉价食材
选项A："全部买下" → lowFood + 20, money - 500
选项B："少量购买" → lowFood + 5, money - 150

事件：卫生检查通知
选项A："紧急整顿" → hygiene + 10, money - 200
选项B："蒙混过关" → 50%概率无事，50%概率停业1天
```

## 三、天气系统（WeatherManager）

### 3.1 设计目的

每天模拟不同的天气状况，影响夜市客流和收入，增加每日的策略变化。

### 3.2 天气预设

| 天气ID | 名称 | 客流倍率 | 收入倍率 | 权重 | 描述 |
|--------|------|:--------:|:--------:|:----:|------|
| WEATHER_SUNNY | ☀️ 晴天 | 1.0 | 1.0 | 40 | 阳光明媚，客流量正常 |
| WEATHER_CLOUDY | ⛅ 多云 | 0.9 | 1.0 | 25 | 多云天气，客流稍减 |
| WEATHER_RAINY | 🌧️ 小雨 | 0.7 | 0.9 | 20 | 下着小雨，出行不便 |
| WEATHER_STORM | 🌪️ 暴风雨 | 0.4 | 0.7 | 5 | 狂风暴雨，很少有人出门 |
| WEATHER_HOT | 🌡️ 炎热 | 0.8 | 1.1 | 10 | 天气炎热，夜市更受欢迎 |

### 3.3 刷新机制

```
每天 DayStart → WeatherManager.RefreshWeather(currentDay)

抽取算法：按权重随机选取
  总权重 = Σ(所有天气预设的weight)
  randomValue = Random.Range(0, 总权重)
  遍历天气预设，累加权重，当 randomValue < 累加值时选中该天气

例：
  晴天权重40 → 40/(40+25+20+5+10) = 40/100 = 40%概率
  暴风雨权重5 → 5/100 = 5%概率
```

### 3.4 天气对游戏的影响

| 影响维度 | 计算公式 | 说明 |
|---------|---------|------|
| **客流影响** | `实际客流 = 基础客流 × GetTrafficModifier()` | 晴天1.0，小雨0.7，暴风雨仅0.4 |
| **收入影响** | `实际收入 = 计算收入 × GetIncomeModifier()` | 炎热天气夜市更受欢迎，收入×1.1 |
| **体力消耗** | （预留）雨天走格体力消耗增加 | 后续版本实现 |
| **事件关联** | （预留）特定天气下某些事件概率提升 | 后续版本实现 |

### 3.5 强制天气机制

供事件系统使用：某些事件可以强制改变天气。

```csharp
// 事件触发强制天气
WeatherManager.ForceWeather("WEATHER_RAINY");  // 强制下雨
```

### 3.6 UI 对接

```
WeatherManager.WeatherChanged 事件：
  → UI 显示当前天气图标/名称
  → 显示天气对客流和收入的影响提示
```


## 四、卫生审查系统（InspectionManager）

### 4.1 设计目的

模拟真实夜市卫生检查机制，迫使玩家关注摊位卫生值，在扩张和卫生维护之间做权衡。

### 4.2 检查触发规则

```
每晚对每个营业中的夜市执行检查判定：

触发概率 = 基础概率(5%) + 地块inspectionRate + 卫生值惩罚加成

卫生值惩罚加成：
  totalHygiene < 50 → +25%（高风险、脏乱差）
  totalHygiene < 70 → +10%（中低风险、需要注意）
  totalHygiene ≥ 70 → +0%（卫生合格）

总概率上限：80%（避免极端情况）
```

### 4.3 检查执行规则

```
触发检查后：

夜市总卫生值 ≥ 70 → 通过（无处罚）
  日志："夜市卫生达标，检查通过。"

夜市总卫生值 < 70 → 不通过（处罚）
  → 停业 penaltyClosedRounds 天（默认2天）
  → 罚款 penaltyFineAmount 元（默认1000元）
  日志："卫生检查不通过！停业2天，罚款1000元。"
```

### 4.4 检查参数配置

| 参数 | 默认值 | 说明 |
|------|:-----:|------|
| `hygieneThresholdLow` | 50 | 低卫生阈值（高风险） |
| `hygieneThresholdMedium` | 70 | 中卫生阈值（通过标准） |
| `inspectionBaseRate` | 0.05 | 基础检查概率 5% |
| `penaltyClosedRounds` | 2 | 不通过时的停业天数 |
| `penaltyFineAmount` | 1000 | 不通过时的罚款金额 |

### 4.5 风险等级

| 卫生值范围 | 风险等级 | 触发概率加成 | 建议玩家操作 |
|:---------:|:-------:|:----------:|------------|
| ≥ 85 | 🟢 低风险 | 0% | 保持即可 |
| 70 ~ 85 | 🟢 低风险 | 0% | 注意维护 |
| 55 ~ 70 | 🟡 中风险 | +10% | 建议升级/清洁 |
| < 55 | 🔴 高风险 | +25% | 立即整顿！ |

### 4.6 卫生值的口碑影响

夜市卫生状况直接影响口碑，间接影响收入：

| 卫生值范围 | 口碑加成系数 | 效果 |
|:---------:|:-----------:|------|
| ≥ 90 | ×1.10 | +10% 收入 |
| 80 ~ 90 | ×1.05 | +5% 收入 |
| 70 ~ 80 | ×1.00 | 无加成 |
| < 70 | ×0.95 | -5% 收入 |

### 4.7 强制检查机制

供事件系统调用：某些事件可强制触发卫生检查。

```csharp
// EventManager 中强制执行检查
bool passed = inspectionManager.ForceInspection(tileId);
if (!passed)
{
    // 检查不通过，触发额外事件效果
    eventManager.ExecuteEventEffect(penaltyEvent);
}
```

### 4.8 与摊位卫生值的关系

```
摊位配置：
  StreetVendor.hygiene = 80 （摊贩卫生一般）
  Store.hygiene = 85        （门店卫生较好）
  ChainStore.hygiene = 90   （连锁店卫生好）

夜市总卫生值 = Σ(各摊位卫生值) / 摊位数量（平均值）

提升夜市卫生 ≈ 建设高卫生摊位 + 升级现有摊位
```

## 五、三个系统之间的交互

```
                      EventManager
                      ┌──────────┐
                      │ 随机事件  │
                      └────┬─────┘
           ┌────────────────┼────────────────┐
           │                │                │
           ▼                ▼                ▼
   ┌──────────────┐ ┌──────────────┐ ┌────────────────┐
   │ WeatherManager│ │InspectionMgr│ │ ResourceManager │
   │ 强制天气      │ │ 强制检查    │ │ 执行事件效果    │
   └──────────────┘ └──────────────┘ └────────────────┘
           │                │
           ▼                ▼
   ┌─────────────────────────────────────────┐
   │            EconomyManager               │
   │ 结算时应用天气倍率 × 卫生口碑加成       │

```

### 交互场景示例

| 场景 | 流程 |
|------|------|
| 下雨事件 | EventManager 触发 → WeatherManager.ForceWeather("RAINY") → 当晚结算客流×0.7 |
| 卫生举报事件 | EventManager 触发 → InspectionManager.ForceInspection(tileId) → 卫生低则停业 |
| 节日加成事件 | EventManager 触发 → EconomyManager 结算时临时倍率 → AddMoney |
| 暴风雨+低卫生 | WeatherManager(客流×0.4) + InspectionManager(+25%检查概率) → 高风险组合 |

## 六、玩家策略建议

### 应对随机事件的策略
1. **预留流动资金**（至少2000~5000元）应对突发事件
2. **优先提升摊位卫生**（hygiene ≥ 70 可规避停业风险）
3. **关注天气预告**（炎热天收入更高，可提前备货）

### 风险组合（最坏情况）
```
暴风雨(客流×0.4) + 卫生检查不通过(停业2天) + 罚款1000元
→ 当晚收入几乎为零，还要额外支出
→ 建议：始终保持卫生 ≥ 70，预留应急资金
```

### 收益组合（最佳情况）
```
炎热天气(收入×1.1) + 夜市4级口碑加成(reputation×0.01) + 卫生优秀(×1.05)
→ 三项叠加，收入可达正常的 1.1 × 1.05 × (1+reputation×0.01) 倍
```

## 八、后续扩展方向

1. **天气与事件联动**：特定天气下某些事件概率提升（如雨天→"雨水损坏设备"事件）
2. **季节系统**：不同季节天气权重变化（夏季炎热权重↑，冬季暴风雨权重↑）
3. **连锁事件**：一个事件触发后，后续几天有后续事件
4. **竞争事件**：NPC 夜市可能触发竞争事件，影响玩家客流
5. **玩家成就**：累计触发/规避事件可获得成就
