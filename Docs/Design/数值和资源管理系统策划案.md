# 数值和资源管理系统策划案

## 一、系统概述

数值和资源管理系统是 HUST-Night-Market 的经济核心，负责管理玩家的所有资源（资金、食材、体力、口碑），处理夜晚收入结算、贷款利息等经济逻辑，为夜市/摊位系统的建设与升级提供资源检查和扣费支持，同时包含客流分配、随机事件、天气系统和卫生审查等子系统。

---

```
│  │                 PlayerRuntimeData                          │  │

│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│                        子系统层                                   │
│  ┌──────────────────┐  ┌──────────────────┐  ┌────────────────┐ │
│  │  CustomerManager │  │   EventManager   │  │ WeatherManager │ │
│  │   客流分配系统    │  │   随机事件系统    │  │    天气系统     │ │
│  └──────────────────┘  └──────────────────┘  └────────────────┘ │
│  ┌──────────────────┐  ┌──────────────────┐                     │
│  │ InspectionManager│  │   MarketManager  │                     │

│  └──────────────────┘  └──────────────────┘                     │
└──────────────────────────────────────────────────────────────────┘

子系统间调用关系：
  EconomyManager  → CustomerManager (获取客流分配)
                  → WeatherManager  (获取天气倍率)
                  → ResourceManager (扣费/加钱)
  EventManager    → ResourceManager (执行事件效果)
                  → MarketManager   (停业处罚)
                  → CustomerManager (客流修正)
                  → InspectionManager (强制检查)
  InspectionManager → MarketManager (停业处罚)
  MarketManager   → ResourceManager (资金检查/扣费)
```

## 三、资源类型定义

| 资源类型 | 枚举值 | 数据类型 | 说明 |
|---------|--------|:-------:|------|
| 资金 | Money | int | 玩家当前持有的现金，用于购买地块、建设夜市、升级摊位等 |
| 低端食材 | LowFood | int | 普通食材，摊贩消耗，每晚按摊位配置消耗 |
| 高端食材 | HighFood | int | 高级食材，门店/连锁店消耗 |
| 体力 | Energy | int | 玩家白天的行动资源，走格消耗，有上限 |
| 口碑 | Reputation | int | 夜市/摊位声誉，影响收益加成和客流 |

## 四、资源操作规则

### 4.1 资金规则

| 操作 | 方法 | 规则 |
|------|------|------|
| 检查 | `CheckMoney(amount)` | money >= amount 返回 true |
| 扣除 | `SpendMoney(amount)` | money >= amount 则扣费返回 true；不足返回 false，不扣费 |
| 增加 | `AddMoney(amount)` | 无条件增加，amount 必须 >= 0 |

### 4.2 食材规则

| 操作 | 方法 | 规则 |
|------|------|------|
| 检查低端食材 | `CheckLowFood(amount)` | lowFood >= amount 返回 true |
| 消耗低端食材 | `ConsumeLowFood(amount)` | 不足返回 false，不消耗；足够则扣减 |
| 增加低端食材 | `AddLowFood(amount)` | 无条件增加 |
| 检查高端食材 | `CheckHighFood(amount)` | highFood >= amount 返回 true |
| 消耗高端食材 | `ConsumeHighFood(amount)` | 不足返回 false，不消耗；足够则扣减 |
| 增加高端食材 | `AddHighFood(amount)` | 无条件增加 |

### 4.3 体力规则

| 操作 | 方法 | 规则 |
|------|------|------|
| 检查 | `CheckEnergy(amount)` | energy >= amount 返回 true |
| 消耗 | `ConsumeEnergy(amount)` | 不足返回 false；足够则 energy -= amount |
| 恢复 | `RestoreEnergy(amount)` | energy = Min(energy + amount, maxEnergy) |

### 4.4 口碑规则

| 操作 | 方法 | 规则 |
|------|------|------|
| 增加 | `AddReputation(amount)` | 无条件增加 reputation |
| 查询 | `GetCurrentReputation()` | 返回当前 reputation 值 |

## 五、夜晚收入结算流程

### 5.1 结算入口

由 `EconomyManager.SettleAllMarketsNightIncome()` 触发，在 TurnManager 的 NightSettlement 阶段调用。

### 5.2 结算流程图

```
NightSettlement 开始
  │
  ├─ [EconomyManager] 遍历所有夜市
  │    │
  │    ├─ 跳过 closedRounds > 0 的夜市（停业）
  │    │
  │    ├─ 通过 FindTileConfig(market.tileId) 获取地块配置
  │    │
  │    ├─ 计算地块总客流 = baseTraffic × GetTrafficCapacityMultiplier()
  │    │    │
  │    │    ├─ baseTraffic：地块基础客流（TileConfig）
  │    │    └─ 2级夜市效果：×1.2（客流+20%）
  │    │
  │    ├─ 按各摊位吸引力权重分配客流
  │    │    │
  │    │    ├─ stallAttraction = baseAttraction × 等级系数
  │    │    ├─ 等级系数 = 1 + (level-1) × 0.1
  │    │    └─ trafficShare = totalTraffic × (stallAttraction / totalAttraction)
  │    │
  │    ├─ 对每个摊位：
  │    │    │
  │    │    ├─ 计算偏好倍率 = Σ(偏好 × 客群占比加权)
  │    │    ├─ 有效客流 = trafficShare × 偏好倍率
  │    │    ├─ 收入 = 有效客流 × basePrice × consumePower
  │    │    ├─ 消耗低端食材（ConsumeLowFood）
  │    │    ├─ 消耗高端食材（ConsumeHighFood）
  │    │    └─ 食材不足时：收入 × 0.5（打折惩罚）
  │    │
  │    ├─ 累加该夜市所有摊位收入
  │    │
  │    └─ 夜市4级口碑加成：收入 × (1 + reputation × 0.01)
  │
  ├─ 累加所有夜市收入，调用 AddMoney(totalIncome)
  │
  └─ 结算结束
```

### 5.3 收入公式

```
单个摊位收入 = floor(
    totalTraffic 
    × (stallAttraction / totalAttraction)   // 吸引力权重分配客流
    × CalculatePreferenceMultiplier()        // 客群偏好加权
    × basePrice                              // 客单价
    × consumePower                           // 地块消费力倍率
    × (食材不足 ? 0.5 : 1.0)                 // 食材惩罚
)

夜市总收入 = Σ(各摊位收入)
夜市总收入 = 夜市总收入 × (夜市4级 ? (1 + reputation × 0.01) : 1)
总收入 = Σ(各夜市总收入)
```

## 六、贷款利息处理

### 6.1 参数

| 参数 | 默认值 | 说明 |
|------|:-----:|------|
| interestInterval | 7天 | 利息结算周期 |
| interestRate | 0.1 (10%) | 每期利率 |

### 6.2 规则

```
利息日判定：currentDay % interestInterval == 0

利息金额 = floor(loan × interestRate)

处理逻辑：
    如果 money >= 利息金额：
        从资金扣除（SpendMoney）
    否则：
        不足部分加到贷款本金
        loan += (利息金额 - money)
        money = 0
```

## 七、事务封装（购买/建设/升级）

### 7.1 设计原则

所有涉及资源扣费的操作遵循 **"先检查 → 再扣费 → 最后执行 → 失败回滚"** 的三段式原则。

### 7.2 事务接口

| 方法 | 检查步骤 | 扣费步骤 | 执行步骤 | 回滚 |
|------|---------|---------|---------|------|
| `PurchaseTile` | CanCreateMarket | SpendMoney | TryCreateMarket(tileId) | 创建失败退还费用 |
| `BuildStallTransaction` | CanBuildStall | SpendMoney | BuildStall | 建设失败退还费用 |
| `UpgradeStallTransaction` | CanUpgradeStall | SpendMoney | UpgradeStall | 升级失败退还费用 |
| `UpgradeMarketTransaction` | CanUpgradeMarket | SpendMoney | UpgradeMarket | 升级失败退还费用 |

### 7.3 通用事务流程

```
bool Transaction(参数)
{
    // Step 1: 规则检查
    if (!CanXxx(参数, out reason)) return false;

    // Step 2: 扣费
    if (!SpendMoney(cost)) return false;

    // Step 3: 执行
    if (!Xxx(参数))
    {
        // 回滚：退还费用
        AddMoney(cost);
        return false;
    }

    return true;
}
```

## 八、MarketManager 集成

MarketManager 中以下方法已完成 ResourceManager 的集成：

### 8.1 夜市创建

```
CanCreateMarket(tileConfig):
    ...原有规则检查...
    + CheckMoney(tileConfig.purchasePrice)  // 新增资金检查
    资金不足 → reason="资金不足，无法购买该地块。"

TryCreateMarket(tileConfig):
    CanCreateMarket() → 检查通过
    → SpendMoney(tileConfig.purchasePrice)  // 新增扣费
    → TryCreateMarket(tileId)  // 创建夜市
```

### 8.2 夜市升级

```
CanUpgradeMarket(marketData, out upgradeCost):
    ...原有规则检查...
    upgradeCost = GetNextUpgradeCost(marketData)
    + CheckMoney(upgradeCost)  // 新增资金检查
    资金不足 → reason="资金不足，无法升级夜市。"

UpgradeMarket(tileId):
    CanUpgradeMarket() → 检查通过
    → SpendMoney(upgradeCost)  // 新增扣费
    → 升级夜市等级
```

### 8.3 摊位建设

```
CanBuildStall(marketData, stallConfig):
    ...原有规则检查...
    + CheckMoney(stallConfig.buildCost)  // 新增资金检查
    资金不足 → reason="资金不足，无法建设该摊位。"

BuildStall(tileId, stallConfig):
    CanBuildStall() → 检查通过
    → 创建摊位（扣费由 EconomyManager 事务封装处理）
```

### 8.4 摊位升级

```
CanUpgradeStall(marketData, stallData, stallConfig):
    ...原有规则检查...
    upgradeCost = GetStallUpgradeCost(stallData, stallConfig)
    + CheckMoney(upgradeCost)  // 新增资金检查
    资金不足 → reason="资金不足，无法升级该摊位。"

UpgradeStall(tileId, stallId, stallConfig):
    CanUpgradeStall() → 检查通过
    upgradeCost = GetStallUpgradeCost(stallData, stallConfig)
    → SpendMoney(upgradeCost)  // 新增扣费
    → 升级摊位等级
```

## 九、数值量级等级标准

详见 `Docs/Planning/数值等级规范.md`

**核心原则**：所有数值划分为五个等级，确保数值体系的一致性。

| 等级 | 资金 | 含义 |
|:----:|:----:|------|
| 很少 | 1~500 | 连一个摊贩都建不起 |
| 少 | 500~2,000 | 刚好够建一个摊贩 |
| 中等 | 2,000~10,000 | 能建门店+少许升级 |
| 多 | 10,000~50,000 | 夜市升3级+多个摊位 |
| 很多 | 50,000+ | 接近胜利目标(10万) |

## 十一、客流系统（CustomerManager）

### 11.1 职责

根据地块基础客流、夜市摊位吸引力、客群偏好和竞争强度，为每个摊位分配当晚客流。

### 11.2 核心方法

| 方法 | 说明 |
|------|------|
| `AllocateTraffic(market, tileConfig)` | 简化版：等比例分配客流 |
| `AllocateTraffic(market, tileConfig, stallConfigs)` | 完整版：按吸引力权重分配客流 |
| `CalculatePreferenceMultiplier(stallConfig, tileConfig)` | 计算客群偏好倍率 |
| `ApplyCompetitionPenalty(baseTraffic, competition)` | 竞争强度削减客流 |

### 11.3 客流分配公式

```
竞争削减比例 = min(1, competition × 0.5 / 100)
有效客流 = baseTraffic × (1 - 竞争削减比例)

摊位吸引力 = baseAttraction × (1 + (level-1) × 0.1)
客流占比 = max(0.01, 摊位吸引力 / 总吸引力)
摊位客流 = round(有效客流 × 客流占比)
```

### 11.4 文件位置

`Assets/_Project/Scripts/Customers/CustomerManager.cs`

## 十二、随机事件系统（EventManager）

### 12.1 职责

利用已有的 EventTriggerType 和 EventEffectType 枚举，负责在指定时机触发随机事件、按概率抽取事件池、执行事件效果（资金/食材/体力/口碑/停业等）。

### 12.2 GameEvent 数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| eventId | string | 事件唯一ID |
| eventName | string | 事件显示名称 |
| eventDescription | string | 事件描述文本 |
| triggerType | EventTriggerType | 触发时机 |
| effectType | EventEffectType | 效果类型 |
| effectValue | int | 效果数值（正=增益，负=减益） |
| probability | float | 触发概率（0.0~1.0） |
| eventPoolId | string | 所属事件池ID |
| requireChoice | bool | 是否需要玩家二选一 |
| choiceAText / choiceAValue | string / int | 选项A |
| choiceBText / choiceBValue | string / int | 选项B |

### 12.3 触发时机与效果对应

| 触发时机 | 说明 | 调用方 |
|---------|------|--------|
| OnArriveTile | 玩家到达地块时 | TurnManager / MapManager |
| OnDayStart | 每天开始时 | TurnManager |
| OnNightStart | 夜晚开始时 | TurnManager |
| OnSettlement | 结算过程中 | EconomyManager |
| OnInspection | 卫生检查时 | InspectionManager |
| Manual | 手动或调试触发 | 调试面板 |

| 效果类型 | 说明 |
|---------|------|
| AddMoney | 修改资金 |
| AddLowFood | 修改低端食材 |
| AddHighFood | 修改高端食材 |
| AddReputation | 修改口碑 |
| AddEnergy | 修改体力 |
| ModifyTraffic | 修改客流百分比 |
| ModifyCompetition | 修改竞争强度 |
| ModifyHygiene | 修改卫生值 |
| TriggerInspection | 强制触发卫生检查 |
| CloseMarket | 夜市停业 |

### 12.4 事件池设计

事件池按用途分组，代码中通过 `EventManager.Awake()` → `InitializeDefaultEventPool()` 自动填充：

| 事件池ID | 用途 | 事件数 | 事件ID 前缀 |
|---------|------|:-----:|:----------:|
| EVENT_POOL_ARRIVE | 到达地块触发 | 9 | EVT_ARRIVE_ |
| EVENT_POOL_DAY_START | 每天开始触发 | 7 | EVT_DAY_ |
| EVENT_POOL_NIGHT | 夜晚开始触发 | 8 | EVT_NIGHT_ |
| EVENT_POOL_INSPECTION | 卫生检查时触发 | 5 | EVT_INSPECT_ |
| EVENT_POOL_MANUAL | 手动/调试触发 | 1 | EVT_MANUAL_ |

### 12.5 事件池初始化方式

EventManager 支持两种初始化方式：

1. **代码自动初始化（推荐）**：`Awake()` 中自动调用 `InitializeDefaultEventPool()`，按预设配置填充全部 30 个事件。
2. **Inspector 手动配置**：如果开发者在 Unity 编辑器中预先在 `eventPool` 列表中设置了事件，则跳过自动初始化。

### 12.6 触发流程

```
触发事件(TriggerType)
  │
  ├─ 过滤事件池中所有符合 triggerType 的候选事件
  │
  ├─ 对每个候选事件：
  │    ├─ Random.value < probability? → 触发
  │    │    ├─ requireChoice? → 记住事件，等待 UI 回调 MakeEventChoice()
  │    │    └─ !requireChoice? → 直接执行 ExecuteEventEffect()
  │    └─ 否则 → 跳过
  │
  └─ 返回所有被触发的事件列表（含 EventRuntimeData）
```

- **选项A："给好处费"** → 直接扣除 500 元，跳过本次检查
- **选项B："公事公办"** → 正常执行卫生检查，若卫生不足可能受罚

### 12.8 二选一事件处理流程

```
EventManager.TriggerEvents() 触发事件
  → 检测到 requireChoice == true
  → 返回 EventRuntimeData（不执行效果）
  → UI 弹窗展示 choiceAText / choiceBText
  → 玩家选择后调用 EventManager.MakeEventChoice(runtimeData, chooseA)
  → ExecuteEventEffect() 执行对应选项效果
  → runtimeData.playerChoice 记录为 "A" 或 "B"
```

### 12.9 文件位置

`Assets/_Project/Scripts/RandomSystem/GameEvent.cs` — 事件数据结构
`Assets/_Project/Scripts/RandomSystem/EventManager.cs` — 事件管理器

## 十四、卫生审查系统（InspectionManager）

### 14.1 职责

夜晚结算时检查夜市卫生状况，触发卫生检查并执行停业处罚。

### 14.2 检查规则

```
触发概率 = 基础概率(5%) + 地块inspectionRate + 卫生值修正

卫生值修正：
  totalHygiene < 50 → +25%（高风险）
  totalHygiene < 70 → +10%（中低风险）
  totalHygiene ≥ 70 → 无额外加成

通过标准：totalHygiene ≥ 70
不通过处罚：停业2回合 + 罚款1000元
```

### 14.3 核心方法

| 方法 | 说明 |
|------|------|
| `ExecuteNightlyInspections(markets, tileConfigs)` | 对所有夜市执行检查 |
| `TryTriggerInspection(market, tileConfig)` | 判定是否触发检查 |
| `ExecuteInspection(market)` | 执行检查并处罚 |
| `ForceInspection(tileId)` | 强制检查（供事件系统使用） |
| `GetInspectionRiskLevel(market)` | 获取风险评级 |
| `GetHygieneReputationBonus(market)` | 卫生值的口碑加成系数 |

### 14.4 文件位置

`Assets/_Project/Scripts/RandomSystem/InspectionManager.cs`
