# 地块系统设计文档

## 一、系统定位

地块系统负责管理单个地块的静态配置、局内状态和玩家落地后的交互流程。

地图系统回答“地块在哪里、与谁连接、能否走到”；地块系统回答“这个地块是什么、当前属于谁、玩家落地后可以做什么”。

地块系统主要服务：

1. `TileManager`：根据地块类型编排落点交互。
2. `MarketManager`：检查可建设地块并创建夜市。
3. `ResourceManager`：处理资源获取、购买费用和商店交易。
4. `EventManager`：根据事件池触发随机事件。
5. `CustomerManager` / `EconomyManager`：读取地块经营参数。
6. UI：显示地块信息、所有权和可执行操作。

## 二、设计目标

1. 地块静态数据使用 `TileConfig` 配置，不写死在管理器中。
2. 地块局内变化使用 `TileRuntimeData`，不得修改 `ScriptableObject`。
3. 落点交互由 `TileManager` 编排，具体资源和数值修改交给对应系统。
4. 第一版只实现起点、可建设、资源、商店、事件和特殊地块。
5. 地块功能通过 `TileType`、资源类型和事件池ID判断，不使用显示名称判断。
6. 跨系统调用优先使用公开的 `Can...` 和执行接口。

## 三、职责边界

### 1. TileManager负责

1. 按 `tileId` 取得 `TileConfig` 和 `TileRuntimeData`。
2. 根据地块类型生成可执行操作。
3. 检查地块是否允许本次交互。
4. 调用夜市、资源、商店、事件和卫生检查系统。
5. 等待交互完成。
6. 通知 `TurnManager` 进入夜晚结算。

### 2. TileManager不负责

1. 计算移动路径。
2. 投骰和阶段切换。
3. 直接增减资金、食材、口碑或体力。
4. 直接修改 `MarketManager.Markets`。
5. 解释随机事件的条件和效果。
6. 计算夜晚客流和收入。

### 3. TileView负责

`TileView` 是地块的场景表现组件，负责：

1. 绑定对应的 `tileId`。
2. 提供玩家停靠点。
3. 显示选中、可达、不可达和所有权状态。
4. 响应点击并提交 `tileId`。

`TileView` 不保存权威规则数据。地块类型、价格和客流等内容必须从 `TileConfig` 读取。

## 四、静态配置

### 1. TileConfig

当前代码已有：

```csharp
public class TileConfig : ScriptableObject
{
    public string tileId;
    public string tileName;
    public TileType tileType;
    public string regionId;
    public Vector3 position;
    public List<string> nextTileIds;

    public bool canPurchase;
    public int purchasePrice;
    public int rentCost;

    public int baseTraffic;
    public float consumePower;
    public float studentRatio;
    public float teacherRatio;
    public float touristRatio;
    public float residentRatio;

    public float competition;
    public float inspectionRate;

    public ResourceType resourceType;
    public string eventPoolId;
}
```

### 2. 字段分组

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 标识 | `tileId`、`tileName`、`tileType`、`regionId` | 地块身份和分类 |
| 地图 | `position`、`nextTileIds` | 场景位置和连接关系 |
| 经营 | `canPurchase`、`purchasePrice`、`rentCost` | 地块购买与经营成本 |
| 客流 | `baseTraffic`、`consumePower`、四类客群比例 | 夜晚客流和收益输入 |
| 风险 | `competition`、`inspectionRate` | NPC分流与卫生检查输入 |
| 交互 | `resourceType`、`eventPoolId` | 资源和随机事件入口 |

地块系统维护字段语义，但不负责计算经营结果。

## 五、运行时数据

建议新增：

```csharp
[Serializable]
public class TileRuntimeData
{
    public string tileId;
    public OwnerType owner;
    public bool isDiscovered;
    public bool isInteractionCompletedToday;
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `tileId` | 对应的地块配置ID |
| `owner` | 当前所有者：`None`、`Player` 或 `NPC` |
| `isDiscovered` | 是否已向玩家显示完整信息 |
| `isInteractionCompletedToday` | 是否已经完成当天落点结算 |

MVP阶段如果不做地图迷雾，可以先不使用 `isDiscovered`。

`TileRuntimeData` 不重复保存价格、客流和客群比例。静态数值始终从 `TileConfig` 读取。

夜市等级、摊位列表和停业回合继续保存在 `MarketRuntimeData`，不得复制到地块运行时数据。

## 六、当前地块类型

第一版只处理六种地块：

### 1. Start

起点地块用于玩家开局定位，也是普通道路节点。

规则：

1. `canPurchase` 必须为 `false`。
2. 默认不提供资源和经营收益。
3. 玩家落地后可以直接结束交互。
4. 经过起点奖励暂不实现。

### 2. Buildable

可购买并建设夜市的地块。

根据运行时状态提供：

1. 无主且没有夜市：查看信息、购买并创建夜市。
2. 玩家拥有：打开夜市管理界面。
3. NPC拥有：查看信息，不能购买。

购买前必须检查：

1. `tileType == TileType.Buildable`。
2. `canPurchase == true`。
3. `TileRuntimeData.owner == OwnerType.None`。
4. `MarketManager.GetMarket(tileId) == null`。
5. 玩家资金不少于 `purchasePrice`。
6. `MarketManager.CanCreateMarket` 检查通过。

全部检查通过后，由上层交互流程统一执行：

```text
ResourceManager扣除purchasePrice
-> MarketManager.TryCreateMarket
-> TileRuntimeData.owner设置为Player
-> 刷新地块和夜市UI
```

任一步失败都必须恢复之前已经发生的修改，不能留下已扣费但夜市未创建的状态。

### 3. Resource

资源地块根据 `resourceType` 提供一种资源：

```csharp
Money
LowFood
HighFood
Reputation
Energy
```

规则：

1. `resourceType` 不能为 `None`。
2. 地块系统只提供资源类型和地块ID。
3. 具体获得数量由 `ResourceManager` 或资源配置决定。
4. 同一天是否可以重复获得资源由 `isInteractionCompletedToday` 控制。

MVP可使用固定产量。后续如果不同资源点需要不同产量，应增加独立资源点配置，不持续向 `TileConfig` 增加专用字段。

### 4. Shop

商店地块用于购买食材或其他经营资源。

规则：

1. 落地后打开商店界面。
2. 商品、价格和库存由商店或资源系统维护。
3. 地块系统只负责开始和结束商店交互。
4. 玩家关闭商店界面后视为本次交互完成。

### 5. Event

事件地块通过 `eventPoolId` 请求 `EventManager` 抽取事件。

规则：

1. `eventPoolId` 不能为空。
2. 地块系统不解释事件条件、权重和效果。
3. 事件系统返回完成结果后才能结束地块交互。
4. 同一天是否重复触发由事件规则和地块运行时状态共同决定。

推荐流程：

```text
TileManager.BeginTileInteraction
-> EventManager.TryTriggerEvent(eventPoolId)
-> 显示事件结果
-> TileManager.CompleteTileInteraction
```

### 6. Special

特殊地块用于市场监督局或其他不能归入通用类型的规则。

第一版建议只实现市场监督局：

1. 落地后调用卫生检查系统。
2. 检查目标和结果由卫生检查系统决定。
3. 地块系统只传递地块ID和交互请求。

特殊地块不能通过 `tileName` 判断行为。后续如果出现多种特殊地块，应增加稳定的特殊规则ID或独立配置类型。

## 七、交互信息

建议使用：

```csharp
public class TileInteractionInfo
{
    public string tileId;
    public TileType tileType;
    public List<TileActionType> availableActions;
    public string unavailableReason;
}
```

建议的 `TileActionType`：

```csharp
public enum TileActionType
{
    None,
    ViewInfo,
    PurchaseAndCreateMarket,
    OpenMarketPanel,
    CollectResource,
    OpenShop,
    TriggerEvent,
    TriggerSpecialRule
}
```

交互信息只描述当前可执行操作，不直接包含其他系统的可变数据。

## 八、交互流程

### 1. 开始交互

只有 `GamePhase.TileInteraction` 阶段允许开始地块交互。

流程：

```text
读取PlayerRuntimeData.currentTileId
-> MapManager.GetTileConfig
-> 获取TileRuntimeData
-> TileManager.GetInteractionInfo
-> UI显示可执行操作
-> 玩家选择或系统自动执行
```

### 2. 自动与手动交互

建议：

| 地块类型 | 交互方式 |
| --- | --- |
| `Start` | 自动结束 |
| `Buildable` | 玩家选择购买或打开夜市面板 |
| `Resource` | 自动结算并显示结果 |
| `Shop` | 玩家操作商店界面 |
| `Event` | 自动抽取事件并显示结果 |
| `Special` | 根据特殊规则自动或手动执行 |

### 3. 完成交互

交互完成后：

1. 根据规则更新 `isInteractionCompletedToday`。
2. 刷新地块和资源UI。
3. 清理当前交互状态。
4. 调用 `TurnManager.NotifyTileInteractionFinished()`。

`TileManager` 必须防止同一次落点重复调用完成接口。

## 九、建议公开接口

```csharp
public bool InitializeTiles(MapConfig mapConfig, out string reason);

public TileRuntimeData GetTileRuntimeData(string tileId);
public OwnerType GetTileOwner(string tileId);
public bool SetTileOwner(string tileId, OwnerType owner);

public TileInteractionInfo GetInteractionInfo(string tileId);
public bool BeginTileInteraction(string tileId, out string reason);
public void CompleteTileInteraction();

public void ResetDailyInteractionState();
```

建议事件：

```csharp
public event Action<string> TileInteractionStarted;
public event Action<string> TileInteractionCompleted;
public event Action<string, OwnerType> TileOwnerChanged;
```

## 十、跨系统接入

### 1. MapManager

地块系统通过地图系统查询静态配置：

```csharp
TileConfig tileConfig = mapManager.GetTileConfig(tileId);
```

地块系统不自行维护第二份 `TileConfig` 查询表，除非后续统一数据系统明确要求。

### 2. TurnManager

玩家移动完成后进入 `TileInteraction` 阶段，由 `TileManager` 开始落点交互。

地块交互完成后调用：

```csharp
turnManager.NotifyTileInteractionFinished();
```

### 3. MarketManager

创建夜市时调用：

```csharp
marketManager.CanCreateMarket(tileConfig, out reason);
marketManager.TryCreateMarket(tileConfig, out marketData);
```

地块系统只在创建成功后更新 `TileRuntimeData.owner`。

### 4. ResourceManager

资源系统负责：

1. 检查和扣除地块购买费用。
2. 发放资源地块奖励。
3. 处理商店交易。
4. 返回资源修改是否成功。

地块系统不得直接修改 `PlayerRuntimeData.money`、食材、口碑或体力。

### 5. EventManager

事件系统根据 `eventPoolId` 处理：

1. 事件条件。
2. 随机权重。
3. 事件效果。
4. 持续时间。

地块系统等待事件结束通知后完成交互。

### 6. CustomerManager与EconomyManager

夜晚结算系统按夜市所在的 `tileId` 读取：

1. `baseTraffic`
2. `consumePower`
3. `studentRatio`
4. `teacherRatio`
5. `touristRatio`
6. `residentRatio`
7. `competition`
8. `rentCost`
9. `inspectionRate`

这些是原始配置值，最终结果由数值系统统一计算。

## 十一、配置校验

### 1. 通用校验

1. `tileId` 不能为空。
2. `tileName` 不能为空。
3. `regionId` 不能为空。
4. `purchasePrice`、`rentCost` 和 `baseTraffic` 不能为负数。
5. `consumePower` 必须大于0。
6. `competition` 和 `inspectionRate` 必须在 `0~1`。
7. 四类客群比例必须在 `0~1`。
8. 四类客群比例之和应接近1。

比例允许误差：

```csharp
Mathf.Abs(totalRatio - 1f) <= 0.001f
```

### 2. 类型校验

| 类型 | 校验规则 |
| --- | --- |
| `Start` | `canPurchase == false` |
| `Buildable` | `canPurchase == true`，购买价格合理 |
| `Resource` | `resourceType != ResourceType.None` |
| `Shop` | 不可购买，不自动发放资源 |
| `Event` | `eventPoolId` 不为空 |
| `Special` | 必须存在可识别的特殊规则配置 |

非 `Buildable` 地块的 `canPurchase` 应为 `false`。

## 十二、地块数量建议

32格华科地图参考分配：

| 类型 | 建议数量 |
| --- | ---: |
| `Start` | 1 |
| `Buildable` | 13 |
| `Resource` | 8 |
| `Shop` | 3 |
| `Event` | 5 |
| `Special` | 2 |

建议原则：

1. 起点附近放置低风险资源点和低价建设地块。
2. 不连续放置过多相同类型。
3. 高客流建设地块应配置更高购买价、租金或竞争强度。
4. 森林公园区域增加资源和事件地块。
5. 光谷商圈增加高消费力、高竞争的建设地块。

## 十三、实现顺序

### 第一阶段：地块数据

1. 新增 `TileRuntimeData`。
2. 初始化全部地块运行时状态。
3. 实现地块配置和状态查询。
4. 实现所有权修改接口。

### 第二阶段：基础交互

1. 实现 `TileManager`。
2. 接入 `Start`、`Resource` 和 `Event`。
3. 实现交互开始、完成和防重复机制。

### 第三阶段：经营交互

1. 接入 `Buildable`。
2. 完成购买、扣费、创建夜市和所有权更新流程。
3. 接入夜市管理面板。
4. 接入 `Shop`。

### 第四阶段：特殊规则与UI

1. 接入市场监督局特殊地块。
2. 显示地块详细信息。
3. 显示所有权和可执行操作。
4. 完成地块交互流程测试。

## 十四、验收标准

1. 每个地块都能按ID取得静态配置和运行时状态。
2. 玩家落地后能进入与地块类型对应的交互。
3. 起点地块可以正常结束交互。
4. 资源地块能调用资源系统并防止错误重复结算。
5. 商店地块能打开和关闭商店流程。
6. 事件地块能使用正确的事件池。
7. 可建设地块能完成检查、扣费、创建夜市和更新所有权。
8. 创建夜市失败时不会遗留错误扣费或所有权。
9. 特殊地块不依赖显示名称判断规则。
10. 地块系统不直接修改资源、夜市和事件系统的内部数据。
11. 交互完成后能正确进入夜晚结算阶段。
12. 所有字段和接口遵守项目命名约定。

## 十五、暂不实现

1. 交通和传送地块。
2. 地块拍卖、交易和收购。
3. 复杂NPC地块所有权变化。
4. 经过地块时触发效果。
5. 地块升级。
6. 地图迷雾和探索奖励。
7. 大量特殊地块专用逻辑。
