# 地图系统设计文档

## 一、系统定位

地图系统负责加载地图配置、维护地块连接关系、查询地块、计算玩家可达范围并生成移动路径。

地图是白天行动和夜晚经营结算的共同基础，但地图系统只负责静态地图结构与移动规则，不直接处理地块落点效果、资源变化、夜市建设和经济结算。

地图系统主要服务：

1. `GameManager`：初始化当前地图和玩家起始位置。
2. `TurnManager`：投骰后查询可达地块并校验移动目标。
3. 玩家移动表现：取得按顺序排列的移动路径和场景坐标。
4. `TileManager`：按 `tileId` 查询落点对应的 `TileConfig`。
5. UI：显示地图、可达范围、目标路径和地块基础信息。
6. 客流与经济系统：按 `tileId` 查询地块经营参数。

## 二、设计目标

### 1. 核心目标

1. 使用配置驱动地图，不在代码中写死华科地图的地块与连接关系。
2. 支持分支和环路，不限制为单向圆环地图。
3. 玩家可以选择距离为 `1` 到骰子点数之间的任意可达地块。
4. 移动合法性和实际步数统一由地图系统计算。
5. 地图配置、场景表现和运行时状态通过字符串 ID 关联。
6. 地图规则不依赖场景对象，场景对象缺失时仍能完成路径计算。

### 2. MVP目标

第一张华科地图建议包含约 32 个地块，并满足：

1. 所有地块都能通过 `tileId` 查询。
2. 玩家可以从起点到达全部有效地块。
3. 地图包含分支和环路，可产生路线选择。
4. 投骰后可以正确显示可达范围和最短路径。
5. 地图可以支持完整的白天移动与落点交互流程。

## 三、职责边界

### 1. MapManager负责

1. 加载并校验当前 `MapConfig`。
2. 建立 `tileId -> TileConfig` 查询表。
3. 查询地图、地块和相邻地块。
4. 根据当前位置、骰子点数和体力计算可达范围。
5. 计算当前位置到目标地块的合法路径。
6. 提供地图初始化和玩家移动事件。
7. 为场景表现提供地块配置位置。

### 2. MapManager不负责

1. 投骰和回合阶段切换。
2. 扣除玩家体力或资金。
3. 执行地块落点效果。
4. 修改地块所有权。
5. 创建或升级夜市。
6. 生成资源或随机事件。
7. 计算客流和夜晚收益。

## 四、地图配置

### 1. MapConfig

当前代码已有：

```csharp
public class MapConfig : ScriptableObject
{
    public string mapId;
    public string mapName;
    public string startTileId;
    public int maxDay;
    public int initialMoney;
    public int loanAmount;
    public float victoryMultiplier;
    public int interestInterval;
    public float interestRate;
    public List<TileConfig> tileList;
}
```

地图系统直接使用：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mapId` | `string` | 地图唯一ID，例如 `MAP_HUST` |
| `mapName` | `string` | 地图显示名称 |
| `startTileId` | `string` | 玩家开局所在的地块ID |
| `tileList` | `List<TileConfig>` | 地图包含的全部地块 |

`maxDay`、初始资源、贷款和利息等字段由游戏流程与经济系统读取，地图系统不负责解释这些数值。

### 2. 地块连接字段

地图拓扑使用 `TileConfig` 中的字段：

```csharp
public string tileId;
public Vector3 position;
public List<string> nextTileIds;
```

含义：

| 字段 | 说明 |
| --- | --- |
| `tileId` | 地图节点的唯一ID |
| `position` | 地块在场景中的参考位置 |
| `nextTileIds` | 与当前地块直接连接的地块ID |

`position` 只用于场景摆放和移动表现，不参与路径合法性判断。

## 五、地图拓扑

### 1. 图结构

地图使用邻接表表示：

```text
TileConfig.tileId -> TileConfig.nextTileIds
```

每个地块是一个节点，每个 `nextTileIds` 条目代表一条可以移动的边。

MVP中的普通道路全部按双向连接处理。若A与B相连，配置必须同时满足：

```text
A.nextTileIds 包含 B
B.nextTileIds 包含 A
```

当前不设计单向道路、传送道路、收费道路和动态封路。

### 2. 区域

`TileConfig.regionId` 用于标识地块所属区域。区域主要服务于：

1. 地图内容组织。
2. 区域事件筛选。
3. 客群和经济数值配置。
4. UI区域名称和区域高亮。

区域不改变基础移动规则。玩家能否移动到某个地块只由连接关系、骰子点数和体力决定。

## 六、可达范围与路径

### 1. 可达范围

玩家投出 `diceValue` 后，从 `PlayerRuntimeData.currentTileId` 开始进行广度优先搜索。

合法目标必须满足：

1. 目标地块存在于当前地图。
2. 目标不是玩家当前所在的地块。
3. 最短距离大于等于 `1`。
4. 最短距离小于等于骰子点数。
5. 玩家当前体力不少于实际移动步数。
6. 路径中的全部连接都有效。

玩家可以少走，不要求用完全部骰子点数。

### 2. 返回结果

建议使用：

```csharp
public class ReachableTileResult
{
    public string tileId;
    public int requiredSteps;
    public List<string> pathTileIds;
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `tileId` | 可选择的目标地块 |
| `requiredSteps` | 到达目标所需的最少步数 |
| `pathTileIds` | 从当前位置到目标的完整路径 |

UI可以根据结果显示目标高亮、所需步数和路径预览。

### 3. 路径算法

MVP道路没有权重，使用广度优先搜索取得最短路径。

存在多条相同长度路径时，按 `nextTileIds` 的配置顺序选择第一条路径，保证结果稳定且便于测试。

必须使用已访问集合，防止环路造成无限搜索。

### 4. 暂不支持

第一版不支持：

1. 不同道路消耗不同体力。
2. 天气改变道路消耗。
3. 道路临时关闭。
4. 单向道路。
5. 移动途中改变目标。
6. 传送或交通功能。

## 七、移动流程

推荐流程：

```text
TurnManager.RollDice
-> MapManager.GetReachableTiles
-> UI显示合法目标
-> 玩家选择targetTileId
-> MapManager.IsMoveTargetValid
-> MapManager.TryGetPath
-> ResourceManager检查并扣除体力
-> TurnManager进入MovePlayer
-> 玩家表现沿pathTileIds移动
-> 更新PlayerRuntimeData.currentTileId
-> TurnManager进入TileInteraction
-> TileManager处理落点交互
```

体力规则：

```text
每移动1步消耗1点体力
```

体力应在移动开始前扣除。地图系统只返回所需步数，不直接修改玩家资源。

移动完成前不能开始落点交互。只有玩家位置成功更新后，才能通知 `TurnManager.NotifyPlayerMoveFinished()`。

## 八、建议公开接口

```csharp
public bool InitializeMap(MapConfig mapConfig, out string reason);
public MapConfig CurrentMap { get; }

public bool ContainsTile(string tileId);
public TileConfig GetTileConfig(string tileId);
public IReadOnlyList<TileConfig> GetAllTiles();
public IReadOnlyList<TileConfig> GetNeighborTiles(string tileId);

public List<ReachableTileResult> GetReachableTiles(
    string startTileId,
    int maxSteps,
    int availableEnergy);

public bool TryGetPath(
    string startTileId,
    string targetTileId,
    int maxSteps,
    out List<string> pathTileIds);

public bool IsMoveTargetValid(
    string startTileId,
    string targetTileId,
    int maxSteps,
    int availableEnergy,
    out int requiredSteps,
    out string reason);
```

建议事件：

```csharp
public event Action<MapConfig> MapInitialized;
public event Action<string> TileSelected;
public event Action<string, string> PlayerMoved;
```

事件只传递必要ID，需要完整配置的监听方通过公开接口查询。

## 九、与现有系统接入

### 1. GameManager

新游戏初始化顺序：

1. `GameManager` 保存当前 `MapConfig`。
2. 调用 `MapManager.InitializeMap(mapConfig)`。
3. 将 `PlayerRuntimeData.currentTileId` 设置为 `mapConfig.startTileId`。
4. 地块系统初始化该地图的运行时地块状态。

地图初始化失败时不能继续进入第一天。

### 2. TurnManager

当前接口：

```csharp
SelectMoveTarget(string targetTileId, int requiredSteps)
```

调用方可以伪造 `requiredSteps`。接入地图系统后建议改为：

```csharp
SelectMoveTarget(string targetTileId)
```

由 `TurnManager` 内部调用 `MapManager.IsMoveTargetValid` 取得实际步数和路径。

### 3. TileManager

玩家移动结束后，`TileManager` 使用：

```csharp
MapManager.GetTileConfig(playerRuntimeData.currentTileId)
```

取得落点配置并开始交互。地图系统不判断具体交互效果。

### 4. CustomerManager与EconomyManager

夜晚结算系统按夜市的 `tileId` 查询 `TileConfig`，读取：

1. `baseTraffic`
2. `consumePower`
3. 四类客群比例
4. `competition`
5. `rentCost`
6. `inspectionRate`

地图系统只提供原始配置，不写入天气、事件、口碑或夜市等级修正。

## 十、配置校验

`MapManager.InitializeMap` 必须校验地图配置。

### 1. 阻止初始化的错误

1. `MapConfig` 为空。
2. `mapId` 为空。
3. `startTileId` 为空或不存在。
4. `tileList` 为空。
5. 列表中存在空的 `TileConfig`。
6. 存在空 `tileId`。
7. `tileId` 重复。
8. `nextTileIds` 引用了不存在的地块。
9. 起点没有任何有效连接。

### 2. 配置警告

1. 普通道路连接不是双向。
2. 存在从起点不可达的孤立地块。
3. 地块的 `position` 完全重合。
4. 地块的 `regionId` 为空。
5. `nextTileIds` 包含自身ID。
6. `nextTileIds` 中存在重复ID。

## 十一、华科地图结构建议

地图建议按区域组织：

| 区域 | 定位 | 设计倾向 |
| --- | --- | --- |
| 校内生活区 | 前期稳定区域 | 路线简单，可建设地块较多 |
| 校内教学区 | 校园核心区域 | 分支较多，连接生活区与其他区域 |
| 光谷商圈 | 中后期经营区域 | 距离较远，可形成路线取舍 |
| 东湖/森林公园 | 资源与游客区域 | 资源和事件地块较多 |

拓扑建议：

1. 主环路保证大部分地块可以稳定到达。
2. 设置2至4处分支，形成短路线与长路线选择。
3. 避免连续过多相同类型地块。
4. 起点附近安排前期可用的资源和低价建设地块。
5. 高价值区域应需要更多移动成本或经过更长路径。

## 十二、实现顺序

### 第一阶段：地图初始化

1. 实现 `MapManager`。
2. 建立地块查询表。
3. 实现配置校验。
4. 初始化玩家起点。

### 第二阶段：路径系统

1. 实现相邻地块查询。
2. 实现广度优先搜索。
3. 返回可达目标、步数和路径。
4. 编写分支、环路和无效配置测试。

### 第三阶段：回合接入

1. 修改 `TurnManager.SelectMoveTarget`。
2. 接入玩家当前位置和体力。
3. 保存当前移动路径。
4. 接入移动表现。
5. 移动完成后进入地块交互。

### 第四阶段：正式地图配置

1. 创建华科地图 `MapConfig`。
2. 创建约32个 `TileConfig`。
3. 配置全部邻接关系和场景位置。
4. 验证所有地块从起点可达。

## 十三、验收标准

1. 新游戏能从 `startTileId` 正确初始化玩家位置。
2. 地图能按ID查询全部地块。
3. 投出1至6后，可达范围计算正确。
4. 玩家可以少走，但不能超过骰子点数或当前体力。
5. UI不能选择不可达或不存在的地块。
6. 分支和环路不会造成死循环。
7. 相同配置每次返回相同的最短路径。
8. 移动表现严格按照地图系统返回的路径执行。
9. 错误配置能在初始化阶段给出明确提示。
10. 地图系统不直接修改资源、地块所有权、夜市或经济数据。

## 十四、暂不实现

1. 交通和传送功能。
2. 单向道路。
3. 动态封路。
4. 不同道路权重。
5. 多层和室内地图。
6. 完整NPC棋子行动。
7. 自动地图生成。
8. 地图编辑器插件。
9. 真实华科地图的高精度还原。
