# 《HUST Night Market》当前版本游戏设计文档

## 1. 项目概述

《HUST Night Market》是一款以校园夜市经营为主题的回合制经营策略游戏。玩家从校园地图起点出发，通过掷骰移动、到达地块、触发事件、购买夜市、建设摊位、夜间结算收益等循环，在限定天数内积累资金，偿还贷款并达成财富目标。

当前版本采用 Unity 制作，核心体验已经围绕“地图移动 + 夜市经营 + 随机事件 + 夜晚结算”搭建完成。游戏场景由主菜单场景 `S01_MainMenu_test1` 进入正式游玩场景 `S02_Game_HUST_test1`，当前构建设置中也主要使用这两个测试场景。

## 2. 设计定位

### 2.1 游戏类型

- 类型：回合制经营策略 / 校园题材模拟经营
- 视角：地图棋盘式移动 + UI 面板经营
- 单局目标：在限定天数内通过经营夜市积累足够资金
- 核心节奏：白天移动与决策，夜晚经营与结算

### 2.2 目标用户

游戏面向对轻量经营、校园题材、随机事件和策略收益规划感兴趣的玩家。当前版本更偏课程项目与原型展示，强调系统闭环、玩法可解释性和功能完整度。

### 2.3 核心体验

玩家需要在有限时间和资源下做出路线、投资和经营决策：

- 今天走到哪里？
- 是否购买当前地块并建设夜市？
- 夜市优先升级还是先建设更多摊位？
- 食材、体力、贷款和资金如何平衡？
- 天气、事件和卫生检查带来的风险如何应对？

## 3. 世界观与主题

游戏发生在华中科技大学风格的校园夜市环境中。玩家扮演校园夜市经营者，从启动资金与贷款开始，在校园不同区域寻找适合经营的位置，建设摊位，吸引学生、教师、游客和居民等不同客群，最终将夜市做大。

主题关键词：

- 校园创业
- 夜市烟火气
- 路线选择
- 小成本经营
- 随机事件
- 贷款压力
- 卫生监管

## 4. 核心玩法循环

当前版本的主循环如下：

1. 每日开始：刷新天气，触发每日事件，恢复行动能力。
2. 掷骰：玩家获得当日可移动步数。
3. 选择地块：系统高亮可到达地块，玩家选择目标。
4. 移动到达：玩家棋子移动到目标地块。
5. 地块交互：显示当前地块信息，触发到达事件或进行购买/经营相关操作。
6. 进入黑夜：玩家点击“进入黑夜”后进入夜晚结算。
7. 夜晚结算：根据夜市、摊位、客流、天气、食材、口碑等计算收益。
8. 检查与贷款：处理卫生检查、随机事件、贷款利息。
9. 天数推进：进入下一天，直到达成胜负条件。

## 5. 主要系统设计

### 5.1 回合与阶段系统

游戏通过阶段控制玩家行为。当前阶段包括：

- `Init`：初始化地图、玩家和运行数据。
- `DayStart`：每日开始，刷新天气和每日事件。
- `RollDice`：等待玩家掷骰。
- `ChooseMove`：根据骰子点数选择可到达地块。
- `MovePlayer`：玩家移动到目标地块。
- `TileInteraction`：处理地块信息、事件、购买等交互。
- `NightSettlement`：夜晚营业收入结算。
- `DayEnd`：一天结束，处理利息和胜负判断。
- `GameWin`：达成目标后进入胜利提示，可继续无尽模式。
- `GameLose`：限定天数结束但未达成目标。

这一设计让游戏的每一步行为都有明确状态，方便 UI、按钮、事件和结算逻辑统一控制。

### 5.2 地图与地块系统

地图配置由 `MAP_TEST` 管理，当前测试地图包含 36 个地块，起点为 `T01`。每个地块由 `TileConfig` 配置，主要数据包括：

- 地块 ID 与名称
- 地块类型
- 邻接地块
- 购买价格
- 基础客流
- 消费能力
- 客群比例
- 卫生检查概率
- 事件池 ID

当前地块类型包括：

- 起点地块
- 可购买地块
- 资源地块
- 事件地块
- 特殊地块

当前版本中原商店地块已按需求转为事件地块，相关事件池统一使用 `EVENT_POOL_ARRIVE`，保证到达地块时能够进入统一的事件逻辑。

### 5.3 移动系统

玩家每日通过掷骰获得移动步数。系统会根据当前位置、地图邻接关系、骰子点数和体力判断可到达地块。玩家选择目标后，角色移动到目标地块，并进入地块交互阶段。

移动系统的作用不只是空间移动，也承担了经营决策的一部分：玩家需要规划路线，选择更适合经营、补给或触发事件的地块。

### 5.4 地块交互系统

玩家到达地块后，右侧信息栏常驻显示当前所在地块信息，包括：

- 类型
- 名称
- 购买价格

地块交互行为由地块类型和运行状态决定。当前已实现或接入的交互包括：

- 查看地块信息
- 购买地块并创建夜市
- 打开夜市面板
- 采集资源
- 触发事件
- 结束交互

当前版本也支持在掷骰时自动结束未完成的地块交互，减少玩家卡在交互阶段无法继续行动的问题。

### 5.5 夜市系统

夜市是游戏的核心经营对象。玩家可以在可购买地块上购买并创建夜市。每个夜市包含：

- 所在地块
- 当前等级
- 最大摊位数
- 已建设摊位列表
- 总吸引力
- 总卫生值
- 停业回合数

夜市等级规则：

- 1 级：基础夜市，可容纳 1 个摊位。
- 2 级：可容纳 2 个摊位，升级费用约 2000。
- 3 级：可容纳 3 个摊位，解锁更高阶摊位，升级费用约 5000。
- 4 级：可容纳 4 个摊位，获得口碑加成，升级费用约 10000。

夜市系统的策略点在于：玩家需要判断是先铺更多夜市、升级已有夜市，还是优先建设高收益摊位。

### 5.6 摊位系统

摊位是夜市产生收益的基础单位。当前项目中配置了多个摊位，例如炒饭、烧烤、热干面、咖啡、轻食、炸串等。摊位配置包含：

- 摊位名称
- 建设费用
- 升级费用
- 基础客单价
- 基础吸引力
- 食材消耗
- 卫生值
- 不同客群偏好
- 解锁所需夜市等级

摊位收入不只是简单固定收益，而是会受客流、吸引力、客群偏好、天气、消费能力和食材供给影响。

### 5.7 经济结算系统

夜晚结算是游戏收益的主要来源。当前收入逻辑大致为：

1. 读取夜市所在地块的基础客流。
2. 叠加夜市等级带来的客流承载修正。
3. 叠加天气对客流的影响。
4. 按摊位吸引力分配客流。
5. 根据摊位与地块客群匹配度修正有效客流。
6. 计算客流 × 客单价 × 地块消费力 × 天气收入倍率。
7. 扣除或消耗食材。
8. 食材不足时降低收益。
9. 高等级夜市可根据口碑获得额外收益加成。

这一设计让收益和玩家的建设选择、地块选择、资源储备都产生关联。

### 5.8 资源与贷款系统

玩家运行数据包括：

- 金钱
- 低端食材
- 高端食材
- 口碑
- 体力
- 贷款

当前地图配置为：

- 初始资金：3000
- 初始贷款：7000
- 最大天数：30
- 利息周期：7 天
- 利息率：10%
- 胜利目标倍率：10 倍

胜利目标计算方式为：

> 胜利目标 = (初始资金 + 初始贷款) × 胜利倍率

在当前配置下，胜利目标为：

> (3000 + 7000) × 10 = 100000

贷款系统会在固定周期处理利息。若玩家资金不足以支付利息，不足部分会追加到贷款中，形成资金压力。

### 5.9 随机事件系统

事件系统分为不同触发时机与事件池。当前核心事件池包括：

- `EVENT_POOL_ARRIVE`：到达地块事件。
- `EVENT_POOL_DAY_START`：每日开始事件。
- `EVENT_POOL_NIGHT`：夜晚开始事件。
- `EVENT_POOL_INSPECTION`：卫生检查事件。

事件效果包括：

- 增减金钱
- 增减低端食材
- 增减高端食材
- 增减体力
- 增减口碑
- 调整客流
- 调整卫生
- 触发卫生检查
- 关闭夜市

当前事件信息通过消息栏显示，减少额外弹窗对流程的打断。

### 5.10 天气系统

每日开始时刷新天气。当前天气包含：

- 晴天：客流与收入正常。
- 多云：客流略低。
- 小雨：客流和收入下降。
- 暴雨：显著降低客流和收入。
- 炎热：客流略低但消费能力更强。

天气通过两个倍率影响经营：

- 客流倍率
- 收入倍率

天气让玩家即使做出相同经营行为，每天收益也会产生变化，增强经营波动和风险感。

### 5.11 卫生检查系统

夜市卫生值会影响检查风险。系统会根据基础检查概率、地块检查概率和夜市卫生水平判断是否触发检查。

检查逻辑：

- 卫生较高：通常通过。
- 卫生中等：风险上升。
- 卫生较低：检查概率明显提高。
- 检查失败：可能罚款并停业若干回合。

卫生系统让玩家不能只追求高收益，也需要考虑摊位组合和长期稳定性。

## 6. UI 与交互设计

### 6.1 主菜单

主菜单提供：

- 新游戏
- 退出游戏

当前版本中“新游戏”直接进入 S02 游戏场景，不再弹出贷款设置窗口。

### 6.2 游戏主界面

游戏主界面包含：

- 顶部状态栏：天数、阶段、骰子、天气等。
- 左侧行动按钮：掷骰、打开夜市、进入黑夜等。
- 右侧地块信息栏：显示玩家当前所在地块的类型、名称、购买价格。
- 消息栏：显示事件、结算、阶段变化等信息。
- 夜市面板：购买夜市、升级夜市、建设/升级摊位、查看夜市状态。
- 结算弹窗：进入黑夜后展示当晚结算结果。
- 菜单弹窗：返回主菜单、退出游戏等。

### 6.3 信息反馈原则

当前版本将大量反馈放入消息栏，包括：

- 到达事件
- 每日事件
- 夜晚事件
- 结算结果
- 卫生检查结果
- 操作失败原因

这种方式适合原型阶段，能让玩家持续看到系统反馈，也便于演示时解释内部机制。

## 7. 胜负条件

### 7.1 胜利条件

当游戏到达地图配置的最大天数后，若玩家当前金钱达到胜利目标，则判定胜利。

当前配置：

- 最大天数：30 天
- 胜利目标：100000 金钱

胜利后，游戏不会强制结束，而是进入胜利提示与无尽模式，玩家可以选择继续经营。

### 7.2 失败条件

当达到最大天数后，若玩家金钱低于胜利目标，则游戏失败。

失败条件强调经营效率：玩家不仅要活下来，还需要在限定时间内完成资本积累。

## 9. 技术实现概述

### 9.1 架构拆分

当前项目按系统拆分脚本，主要模块包括：

- `GameManager`：全局游戏状态与胜负判断。
- `TurnManager`：每日阶段流转、掷骰和移动阶段。
- `MapManager`：地图数据、路径和可达地块判断。
- `TileManager`：地块运行状态和交互信息。
- `PlayerMover`：玩家棋子移动表现。
- `ResourceManager`：玩家资源读写。
- `MarketManager`：夜市与摊位运行数据。
- `EconomyManager`：夜晚收益、购买、升级、利息。
- `EventManager`：随机事件池和事件效果。
- `WeatherManager`：天气刷新与倍率提供。
- `InspectionManager`：卫生检查与处罚。
- `S02GameUIController`：主界面 HUD 和按钮。
- `MarketPanelController`：夜市面板。
- `TileInteractionPanelController`：地块信息与交互面板。
- `S02PopupUIController`：贷款、菜单、结算和终局弹窗。

### 9.2 数据驱动

地图、地块、摊位等核心内容使用 ScriptableObject 配置，便于后续扩展：

- 新增地块：创建新的 `TileConfig` 并加入地图。
- 修改地块收益：调整基础客流、消费力、客群比例。
- 新增摊位：创建新的 `StallConfig`。
- 调整难度：修改 `MapConfig` 中的初始资金、贷款、天数、胜利倍率和利息。

### 9.3 系统优点

- 回合阶段清晰，便于调试和扩展。
- 数据和逻辑分离，地块与摊位可配置。
- 夜市收益不是固定值，能体现多因素经营策略。
- 随机事件、天气和卫生检查提供不确定性。
- UI 已经能支撑完整原型演示。

## 10. 数值与平衡分析

当前数值目标偏向“快速原型验证”：

- 初始资金较少，促使玩家谨慎投资。
- 初始贷款较高，制造经营压力。
- 30 天限制要求玩家尽快形成收益循环。
- 100000 胜利目标要求玩家不只建设单个夜市，而要扩大经营规模。
- 利息周期为 7 天，给玩家阶段性压力。

后续平衡方向：

- 如果玩家过难达成目标，可以降低胜利倍率或提高基础客流。
- 如果收益膨胀过快，可以提高摊位建设成本或降低天气/口碑加成。
- 如果随机事件影响过强，可以降低事件概率或效果值。
- 如果卫生系统存在感不足，可以提高低卫生处罚力度。
